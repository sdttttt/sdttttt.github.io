#### CI 失败与修复

- 推送后 CI deploy 失败:
  ```
  ERROR error building site: "/content/posts/20200311-Github-Actions-3fw.md:2:1":

  ```
- **根因**:`scripts/gen-covers.ts:injectCoverField` line 266 字符串模板 `---\n${newFm}---` 中,闭合符 `---` 前缺 `\n`
  - 当文件 frontmatter 末尾为 `aliases: [...]\n`(我迁移后所有文章都是这种结构),走 if 分支(`fm.replace`)重写 cover 块后
  - `newFm` 末尾是 `\n`(来自 `+ '\n'`),模板拼接产生 `---\n...\n---` 看似正常
  - **但**当文件**没有 trailing newline** 时,regex `[\s\S]*?\n---` 不匹配(因为根本没有第二个 `---`),`replace` 不替换 → 文件保持原样 → 但原文件 frontmatter 没问题... **矛盾!**
- **真正重现**:本地用 v0.161.1 + 手动写一个无 trailing newline 的测试文件 + 跑 injectCoverField 老逻辑 → 输出文件 frontmatter `aliases: [...]---`(无 `\n` 分隔)

- **修复**:`scripts/gen-covers.ts`
  ```ts
  let newFm = fm.replace(/^cover:\s*\n((?:  .+\n?)+)/m, newCover + '\n');
  // 确保 newFm 以换行结尾,避免与闭合 --- 之间缺少分隔符
  if (!newFm.endsWith('\n')) newFm += '\n';
  const newRaw = raw.replace(/^---\n[\s\S]*?\n---/, `---\n${newFm}---`);
  ```
  + 移除 else 分支多余的 `+ '\n'`(避免双换行)
- **本地验证**:
  - 复现脚本验证 buggy 输出:`aliases: ["/posts/2020031100oh3i/"]---`(无 `\n`)

### 遇到的问题

- **rename/rename 冲突**:本地迁移和 CI auto-fix 在同一文件上往不同方向 rename。教训:涉及大量 rename 的操作前应先 pull 同步 CI 状态 ⚠️
- **rebase 后冲突标记残留**:git 有时不会自动清理 file content 中的冲突标记,只清理 status。教训:rebase 后必须 `hugo --minify` 验证 build,不能只看 `git status` 干净 ⚠️
- **bug 漏检**:本地 v0.161 与 CI v0.165 行为不一致(后者更严格),导致 bug 在本地测不出来。教训:涉及 frontmatter / 严格解析的代码应该用与 CI 同版本的工具验证 ⚠️
- **不区分大小写的本地 + 区分大小写的远程**:APFS 默认 case-insensitive,导致本地文件名 `Github-Actions` 在 Linux CI 上行为可能不同。本次没踩坑,但值得警惕 ⚠️
