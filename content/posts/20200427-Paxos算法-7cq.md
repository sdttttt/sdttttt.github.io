Paxos 算法是分佈式系統中比較重要的一個（協議/算法）.
作為分佈式一致性代名詞的 Paxos 算法號稱是最難理解的算法。

## Problem

首先我們需要知道`Paxos`算法解決了一個什麼問題？

在一個異步分佈式系統中每個`Node`的數據需要儘量保持一致，同時服務又得保持對外可用，這是一個比較腦闊疼的問題，
`Paxos`算法能在可用性和一致性之間保持最佳平衡點。

## Design

在`Paxos`算法體系中，存在三個角色：

- **Proposer**: 負責發起提案(Proposal)，提案帶有一個`提案ID`和一個需要同步的值。

- **Acceptor**: 對提案進行裁決，同意或者拒絕。

- **Learner**: 負責學習提案的結果。

**注意:一個進程可以充當多個角色.**

## Description

Paxos 算法過程主要分為 2 個階段：

**階段一:** 由`Proposer`選擇一個提案 ID 為 a,然後向半數以上的`Acceptor`發起提案 ID 為 a 的 Prepare,
如果一個`Acceptor`收到一個提案 ID 為 X 的 Prepare 請求，它就會遵守一個約定(不再接受比 X 小的提案 ID 的 Prepare, 只接受等於或大於 X 的 Proposal).
