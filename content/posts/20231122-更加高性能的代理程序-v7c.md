在OpenWrt社區逛的時候又發現了一些寶貝。

[https://github.com/daeuniverse/dae](https://github.com/daeuniverse/dae)

DAE（鵝）又是一個代理程序，不過它是透明代理，可以理解成全局代理，所有流量都會經過該軟件。

DAE的特色是使用上了eBPF技術。

- eBPF 是 extended Berkeley Packet Filter 的縮寫，它是一種內核技術，允許開發人員在不修改內核代碼的情況下運行特定的功能。eBPF 的概念源自於 Berkeley Packet Filter（BPF），後者是由貝爾實驗室開發的一種網絡過濾器，可以捕獲和過濾網絡數據包。

其實用最簡單的話來說就是內核插件技術。

![Untitled](Untitled%201.png)

這張圖是DAE對比目前其他流行代理程序的吞吐量。在代理環境中其實沒有什麼區別。主要區別其實是在直連的吞吐量上，領先了其他程序有20倍左右，非常誇張。

---

今天用上了DAE這個玩意，不得不說這玩意的性能確實夠得勁，以前openwrt一分鐘內的負載1-2 左右，換了之後負載直接掉到0.5以下了, 基本在0.1-0.3左右。

分流功能也有，比較可惜的是面板功能不夠多，以及這個玩意手動切換節點也比較繁瑣，目前只有自動換更節點的策略，不過目前還是能湊合著用。

DNS配合mosdns使用:

```jsx
upstream {
  cndns: 'udp://127.0.0.1:6553'
  falldns: 'udp://127.0.0.1:6554'
}

routing {
  request {
    qname(ext:'geosite.dat:category-ads') -> reject
    qname(ext:'geosite.dat:category-ads-all') -> reject
    fallback: cndns
  }

  response {
            # 值得信賴的國外DNS
            upstream(falldns) -> accept
            # 可能被汙染，走一遍國外DNS
            ip(geoip:private) && !qname(geosite:cn) -> falldns
						# 有些固件在DAE攔截DNS後還能正常解析主機名，但是有些固件就不行，這裡過濾.lan（主機名後綴）
						# ip(geoip:private) && !qname(geosite:cn) && !qname(keyword: ".lan") -> falldns
            # 總是同意
            fallback: accept
  }
}
```
