## 维护记录

### 完成的工作

scripts/ 全面审查 + 修复:

**P0 严重**

- `lib/git.ts` 加 `gitExecArgs(args[])`(spawn 数组参数形式,不走 shell)
- `git-commit-push.ts:58` 改用 `gitExecArgs(['commit', '-m', msg])` 替代 `gitExec('commit -m "${escaped}"')`,**修复 shell 注入漏洞**(commit message 含 `$(...)` / 反引号 会被 execSync 解释执行)
- `gen-covers.ts` 用 `lib/args.ts` 统一参数解析 + 在 `--all` / `--files` 模式真正支持 `--dry-run`(原代码忽略此 flag,跑 `--all --dry-run` 会真生成覆盖 220+ 个 SVG)

**P1 重要**

- `format-markdown.ts` 抽出 `buildCommand(args)` 函数 + 包 `import.meta.main` 守卫,避免测试 import 时触发实际 execSync
- `optimize-images.ts` 把 `formatBytes` / `ratio` 改为 export,加测试覆盖
- 新增 `scripts/__tests__/format-markdown.test.ts`(5 个用例:默认 / --check / --check=true 字符串 / 固定 pattern)
- 新增 `scripts/__tests__/optimize-images.test.ts`(8 个用例:formatBytes 三档 / ratio 正负零三种方向 / 大文件 MB / 小数精度)

**验证**

- `deno task test`:41 passed (170 steps),0 failed(原 38 → 41,新增 13 步)
- `hugo --minify` 干净(478 ms)
- `deno check` TypeScript 类型干净

### 决策

- `gitExecArgs` 接收 `args: string[]` 而非拼接字符串 — 整个 commit 流程里只有 commit message 这步有用户输入,其他步骤(setup bot identity / add / pull / push)都是固定字符串,继续用 `gitExec` 没问题,改动最小化
- `format-markdown.ts` 包 `import.meta.main` 而不是改用函数导出模式 — 因为 prettier 是 CLI 而不是 npm 库,无法在测试里 mock 调用,只能覆盖 buildCommand 这层
- `optimize-images.ts` 的 `applyFormat` / `applyResize` 没加测试 — 它们依赖 sharp pipeline 实例,真打 sharp 不算纯函数,留作后续如果要 mock sharp 时再补
