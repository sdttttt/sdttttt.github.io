### 遇到的问题

- **bash 3.2 + `set -u` 下 `$VAR` 紧跟全角字符会被当成变量名的一部分** ⚠️ - `ok "产物已更新：$WASM_ARTIFACT（…"` 直接报 `WASM_ARTIFACT（: unbound variable`（`bin/build-wasm.sh: line 23`），因为 `（` 的多字节序列被当成了名字里的字符。全仓库 grep 出 9 处（`preflight.sh:35/55/58`、`check-links.sh:24`、`artifacts.sh:65/90/94/135`、`build-wasm.sh:23`），统一改成 `${VAR}（`。附注：位置参数 `$1` 后面跟全角是**安全**的（bash 只取一位数字），字母变量名才有这个坑
- **`--check` 第一版会真的改名** ⚠️ - 加了 `--check` 解析却忘了让它隐含 dry-run，于是 `/tmp/checkprobe` 里实测：打印「`--check：需要重命名 1 篇文章`」之后紧接着「`✓ 重命名 1 篇文章成功`」并 exit 0 —— 一个号称只读的门禁把文件改了。修法是 `dryRun = --dry-run || --dryRun || --check`，并补了「文件名必须一个都不动」的端到端测试守住它
- **本机没有全局 `deno`** ⚠️ - `deno: command not found`，但仓库里有 vendored 的 `.tools/deno/bin/deno`（2.9.5）。`bin/lib.sh` 因此负责把 `.tools/deno/bin` 前置进 PATH —— 顺带也解决了 `prettier`：`.tools/deno/bin/prettier` 是 deno 的 shim，自己要求 PATH 上有 deno
- **`bash -n` 只吃第一个文件** ⚠️ - `bash -n bin/*.sh` 静默只检查了第一个，语法错误会漏。`shell_syntax_check()` 改为逐个文件循环

- **「sitemap 里 210 个 `/posts/` loc」是自己数错的** ⚠️ - 一开始把 `grep '/posts/' public/sitemap.xml | wc -l` 得到的 **210** 当成文章数，据此去改 `AGENTS.md` 里那句「= 209 篇」。后来发现那 210 里有 **1 条是 `/posts/` 分区页本身**；去掉它正好 **209**，与 `public/searchindex.json`（同一套 `where site.RegularPages "Type" "in" site.Params.mainSections` 过滤）的 209 条完全对上 → **原有的 209 是对的，改动已回滚**。教训：同一个过滤条件在 sitemap / searchindex / 归档页三处都有产出，**跨口径核对**比盯着一个数字置信
- **theme list 是「叠加」不是「二选一」，引用父主题的路径不等于改了父主题** ⚠️ - 上一轮我引用 `themes/hugo-paper/layouts/partials/head.html:99` 说明 og:image 的管道，被读成「碰了不是你的主题」。实际上 `theme = ["sdttttt-paper", "hugo-paper"]` 让两个主题同时参与渲染，子主题没覆盖的文件本来就由父主题提供 —— 要改必须 fork 进子主题，我从没建议编辑父主题。教训：提到某个文件时要讲清它「由谁提供、渲染时归谁」，否则路径本身就会被当成所有权声明
- **`@reference './app.css';` 是 Tailwind 的编译期指令，却混进了发布 CSS** ⚠️ - Hugo 不跑 PostCSS（`head.html` 里没有 `| postCSS`），所以这行字面量一直躺在 `main.min.css` 里。删掉后 CSS 的 sha256 变了 → 所有 HTML 的 `<link>` 与 `integrity` 属性跟着变，做产物 diff 时必须把这两个都归一化，否则会看到 329 个「差异」
- **minify 后的 HTML 是一整行，`diff` 等于什么都看不见** ⚠️ - 第一次做规范化 diff 时 329 个文件全报「不同」，逐字节都看不出差在哪。解决办法是 `perl -0pi -e 's/</\n</g'` 先把标签拆成行再 diff —— 与上一轮「加 `_index.md` 会把标题清空」是同一类问题：**只能靠改动前后各构建一次做对比**
- **`main.css` 里还留着一处 `url(./theme.png)`** ⚠️ - 来自非 `monoDarkIcon` 分支的 arbitrary utility `.[background:url(./theme.png)_left_center/_auto_theme('spacing.6')_no-repeat]`；本站 `monoDarkIcon = true`，HTML 用的是 `theme.svg` 变体，这条规则永远匹配不到，所以删掉 `theme.png` 不会 404（已 grep 全部产物确认没有任何 HTML 引用它）
