### 遇到的问题

- **Windows 下 `pnpm run build-css` 跑不起来** ⚠️ - pnpm 在 Windows 用 cmd 当脚本壳，`./bin/build-css.sh` 报「'.' 不是内部或外部命令」。改用 Git Bash 直接 `bash bin/build-css.sh`。
- **`node_modules/.bin/unocss` 缺失** ⚠️ - pnpm 11 在这台 Windows / Git Bash 环境下没生成 `.bin` shim，包本体在 `.pnpm` store 里。改用 `node node_modules/.pnpm/@unocss+cli@66.11.0/node_modules/@unocss/cli/bin/unocss.mjs` 直跑，产物与 CI 一致。
- **`artifacts.sh check` 的 JS 新鲜度在本机恒红** ⚠️ - 既有环境问题，与本次改动无关：`core.autocrlf=true` 把仓库里 LF 的 `assets/js/*.js` 检出成 CRLF，`tsc` 重编输出 LF，逐字节比对必然失败（在干净的 HEAD 上用 `--rebuild` 复现确认）。Linux / macOS 上不会这样。
- **指纹文件的哈希基准是「git blob 字节」而不是工作区字节** ⚠️ - 本机 `core.autocrlf=true` 下，工作区文本文件全是 CRLF，直接 `sha256sum` 算出来的指纹提交上去 CI 必红（wasm 指纹在本机恒红也是同一根因）。本次改用临时 `GIT_INDEX_FILE` + `git add -u` 把改动吸进索引、再对每个 blob `git cat-file` 算哈希——blob 字节就是 CI 在 Linux 检出后的 LF 字节。行序也有讲究：`check_css` 是「uno.css 在首行 + 其余按 `LC_ALL=C` 路径排序」后逐行 diff，照着排的。已验证：新指纹与旧指纹的 diff 恰好只有四处预期变化，重算一遍逐字节一致。
- **`pnpm run test` 在本机有一例既有失败** ⚠️ - `check-dead-links.test.ts` 的 `walkMarkdown` 断言期望 `content/about.md`（正斜杠），Node 在 Windows 下返回 `content\about.md`——纯路径分隔符问题，与本次改动无关（干净基线上同样失败）。
