### 遇到的问题

- UnoCSS 的 `@unocss/postcss` 插件官方标注 experimental、不跟 semver —— 升级 UnoCSS 时要盯一下 `main.css` 的字节变化，`artifacts.sh check` 会把差异摆在明面上 ⚠️ - 已在 README 里写明这条约束。
- UnoCSS 的 shortcut 展开不了带变体的工具链（`dark:before:*`），`dark-bg` 只能内联成 `@apply` 或者手写规则 ⚠️ - 现在直接写进 `body` / `.nav-wrapper` 的 `@apply`，并留了注释解释原因。
- 构建不可复现（见上）—— 根因是 on-demand 主题变量 + 并发扫描 ⚠️ - 用 PostCSS 插件排序；`theme: true` 虽然也稳定但体积翻倍，不划算。

### 下次建议

- 如果以后要在 JS 里拼工具类，记得把 `assets/js` 加进 `uno.config.ts` 的 `content.filesystem`，否则类名不会被生成（Tailwind 时代是整目录扫描，不会有这个问题）。
- `bin/artifacts.sh` 的 CSS 指纹仍覆盖整个主题目录（宁可多报）。若觉得 README 改动也要重跑 `build-css` 太啰嗦，可以把 `css_sources` 收窄到 `assets/app.css` + `layouts/**` + `uno.config.ts` + `package.json` + `bun.lock` + `postcss.config.mjs`，但要先确认没有别的输入。
- `custom.css` 里那些为 `:not(#\#)` 炸弹准备的 `!important` 现在大多是多余的，可以逐条验证后删掉（本次没动，避免把迁移和清理搅在一起）。
