### 遇到的问题

- **TS 7 不接受 `module: "none"`** ⚠️ - 原想用 `none` 表达「这是经典脚本」，但 TS 7 允许的取值里没有它（报 `TS6046`）。改用 `preserve`：不做任何模块改写，误加 `import` 时产物会直接在浏览器报错，而不是被悄悄包成 CommonJS。
- **`strict` 会给每个产物加上顶层 `"use strict"`** ⚠️ - `alwaysStrict` 是 `strict` 的连带项，产物第一行多了一句指令。与原先 IIFE 内的 `'use strict'` 语义等价，无害，没有关掉。
- **预览面板里 `requestAnimationFrame` 不触发** ⚠️ - 实测 `rafWorks: false`，所以粒子页这种「只在 rAF 里画」的页面采样不到像素，动画类页面无法用像素验证。改用两条确定性证据：① 屏保走 `startBuild()` 的同步 `tick() + blit()`，能读到真实像素；② 把新旧 JS 分别构建、比较 minify 后的产物。
- **`hugo --minify` 不会渲染草稿页** ⚠️ - 第一次对比时 `/particles/` 的两个脚本没进产物，因为没加 `-D`；两边都加 `-D` 后文件才对得上。

### 下次建议

- 源文件里的 `var` 是从 JS 原样保留的（这次是翻译不是重写）。若想现代化成 `const` / `let`，建议单独一次改动，并靠「minify 后逐字节比较」守住行为不变。
- `assets/ts/` 与 `assets/js/` 都在 `themes/self/` 下，所以改任何一个 `.ts` 都会让 CSS 指纹失配、要求重跑 `build-css`。这是「指纹覆盖整个主题目录」的有意取舍，但如果以后 JS 改动频繁，可以考虑把 `assets/ts/**` 与 `assets/js/**` 从 CSS 指纹里排除——代价是要单独维护一份「哪些文件影响 CSS」的清单。
